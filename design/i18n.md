# i18n — 介面多語言支援

> 「介面多語言支援（i18n）」的設計說明。2026-09 完成實作：EN + zh-TW（預設）、提示詞雙語、設定面板語言切換。

## 目標

1. 網頁介面支援繁體中文（預設）與英文。
2. 分析相片的系統提示詞也翻譯為繁體中文，並依使用者語言選擇。
3. 有 i18n 基底，未來可繼續加入其他語言。

## 架構

### 翻譯字典 `src/lib/i18n/translations.ts`

- `Language = "en" | "zh-TW"`、`Messages`（單一 interface 列出所有 key，新增 key 時兩語系強制同時補齊，編譯期檢查）。
- `translations: Record<Language, Messages>` — en 字典與現行英文字串**逐字相同**（不改變既有英文行為）。
- `normalizeLanguage(value)` — 非 `"zh-TW"` 一律視為 `"en"`（容忍 localStorage 舊值）。
- `getMessages(language)` / `interpolate(template, vars)` — 非 React 工具，供 providers（無 context 環境）使用。
- `SUPPORTED_LANGUAGES` — UI 顯示用（label 用該語言自身名稱：English / 繁體中文）。

插值語法：`{var}` 佔位，`interpolate(t("page.analyzedWith"), { provider, model, seconds })`。

### React 存取 `src/hooks/useI18n.ts`

```ts
const { t, lang, setLanguage } = useI18n();
t("webgpu.manageModels")
t("page.analyzedWith", { provider, model, seconds: "3.2" })
```

- 語言**直接讀自 `AppSettings.language`**（欄位本來就存在，只是以前沒人用）→ 不另建 provider，`setLanguage` 就是 `updateSettings({ language })`，自動持久化到 localStorage。
- 所有 client 元件透過 `useI18n()` 取字串。

### `<html lang>` 同步

`src/components/AppProviders.tsx` 內 `LanguageTagSync`：`useEffect` 寫 `document.documentElement.lang`。

## 預設語言與遷移

- **預設 `zh-TW`**（owner 要求：網頁介面要有繁體中文）。
- `src/lib/settings-manager.ts`：沿用既有的 migration key 模式，新增 `what-do-you-see:migrated-language-zhtw` —— 一次性把已儲存的 `"en"`（舊預設值，代表使用者從未選擇過）改為 `"zh-TW"`。之後使用者在介面選擇的語言不會被再動。

## 提示詞翻譯 `src/lib/providers/system-prompt.ts`

- 原英文版 **逐字保留**（attempt-2 baseline，owner 已驗證），僅補一個 `language` 參數路由。
- 新增 `PRIVACY_ANALYSIS_SYSTEM_PROMPT_ZH`：完整中譯（JSON 格式說明、Guidelines、Go deeper、deep-layer 規則全部對應），關鍵約束：
  - `paras` / `table` 這些 **JSON 欄位名維持英文**（解析器依賴）。
  - 末尾明確要求「以繁體中文輸出 paras 與 table 的內容」。
  - table 的 category 名稱會跟著模型輸出語言（中文提示詞 → 中文 category），`DataTableView` 直接顯示，無需改動。
- API：`getSystemPrompt(language?)` / `buildUserPrompt(exif, language?)` — 預設 `"en"`，舊呼叫點不傳參則行為不變。
- 兩個 live provider（`webgpu.ts`、`llama-server.ts`）改為 `getSystemPrompt(request.language)` + `buildUserPrompt(request.exif, request.language)`；`request.language` 由 `usePhotoAnalysis`（讀 `settings.language`）與 API route（form 欄位 `language`）傳入，兩者**本來就已在傳**，這次才真正生效。
- 英文提示詞**不加** "Respond in English"（保持 baseline 逐字不變，避免動到已驗證的行為）。

## Provider 錯誤訊息

- `webgpu.ts` 的錯誤訊息（無 model / 無影像 / generate 失敗等）用 `getMessages(request.language)` + `interpolate` 依語言輸出。
- `model-cache.ts` 的錯誤保持英文（技術性、且該層無 request 上下文）；`WebGPUSettings` 自己顯示的 "Download cancelled." / "Download failed" 等已轉為 i18n key。
- `/api/analyze` route（self-hosted only）的錯誤保持英文。

## 元件改動清單

全部改用 `t(...)`：`app/page.tsx`、`app/layout.tsx`（metadata description）、`settings/SettingsPanel.tsx`（新增「介面語言」段）、`settings/WebGPUSettings.tsx`、`settings/ProviderConfigForm.tsx`、`settings/ProviderSelector.tsx`、`settings/ConnectionTest.tsx`、`PhotoUpload.tsx`、`ExamplePhotos.tsx`、`EXIFDisplay.tsx`、`ModelDownloadDialog.tsx`、`DownloadProgress.tsx`、`AnalysisResult.tsx`、`DataTableView.tsx`、`LoadingAnimation.tsx`、`MapView.tsx`、`hooks/usePhotoAnalysis.ts`、`hooks/useModelDownload.ts`。

不變：`leaflet-map.tsx`（地圖 attribution 維持原文）、`site.ts` 的 `name`（品牌名）與 `GITHUB_REPO_URL`、範例照片的 credit（版權署名原文）、技術值（URL、model id、EXIF 數值）。

## 設定面板

「介面語言」放在 Settings 面板最上方，`ToggleButtonGroup`（English / 繁體中文），隨其他設定一起 Save 生效。

## 新增語言的步驟

1. `Language` union 加 id；`SUPPORTED_LANGUAGES` 加 entry。
2. `translations` 加新語系（`Messages` interface 會強制補齊所有 key）。
3. 若提示詞也要支援：`system-prompt.ts` 加一份翻譯 + `getSystemPrompt` 路由。
4. `normalizeLanguage` 更新。
